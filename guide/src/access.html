Getting the data

Set-upEverything is anonymous. Logging in only adds longer time-outs and user space. Use astroquery from GitHub main: the PyPI 0.4.11 release writes empty DR1 cutouts. Use schema='dr1'/release=dr1; the Q1 default sedm returns HTTP 401.
uv add "astroquery @ git+https://github.com/astropy/astroquery.git@main"

1. Find the tile

from astroquery.esa.euclid import Euclid
ra, dec = 58.19837, -47.47752          # NGC 1483
tiles = Euclid.launch_job_async(f"""
SELECT mosaic_product_oid, tile_index, filter_name, file_name, file_path, zero_point, creation_date
FROM dr1.mosaic_product
WHERE INTERSECTS(CIRCLE({ra}, {dec}, 0.0001), fov) = 1 AND instrument_name IN ('VIS', 'NISP')
  AND release_name = 'DR1_R2' AND purpose = 'DATA_RELEASE' AND processing_mode = 'WIDE'
ORDER BY tile_index, filter_name, creation_date DESC""").get_results()
# deep-field stacks: release_name='DR1_R1' AND purpose='DATA_RELEASE_DEEP' AND processing_mode='DEEP'

Keep the newest file per tile and band, and prefer the tile whose centre is closest to the target. Check the cutout for zeros: footprints can be larger than the data (in the Deep Fields, use the deep stack). On release day SIA did not yet index DR1.

2. Cutouts (BGSUB mosaics and FLAG maps)

import requests
row = tiles[0]
r = requests.get("https://eas.esac.esa.int/sas-cutout/cutout", timeout=600, params={
    "filepath": f"{row['file_path']}/{row['file_name']}",
    "POS": f"CIRCLE,{ra},{dec},{1.0/60}"})            # half-size 1 arcmin -> 1201 x 1201 pixels
assert r.content.startswith(b"SIMPLE")                # retry otherwise (service busy)
open("cutout.fits", "wb").write(r.content)
# or: Euclid.get_cutout(file_path=..., coordinate=coord, radius=1*u.arcmin, output_file="cutout.fits")

Cutout headers lack MAGZERO, so take zero_point from the table.

3. Full files: background model, RMS, PSF, star masks

aux = Euclid.launch_job_async(f"SELECT stype, file_name FROM dr1.aux_mosaic "
                              f"WHERE mosaic_product_oid = {row['mosaic_product_oid']}").get_results()
name = [a['file_name'] for a in aux if a['stype'] == 'BKG'][0]
Euclid.get_product(file_name=name, schema="dr1", output_file=name)
# or stream: https://eas.esac.esa.int/sas-dd/data?file_name=NAME&release=dr1&RETRIEVAL_TYPE=FILE

The data service answers HTTP range requests (206 Partial Content), so you rarely need a whole file. The cutout service rejects BGMOD and RMS maps, but a 1′ region of them is just a band of rows in the 19200×19200 tile. One range request of ~46 MB (~26 s) replaces the 1.47 GB download, and the result is pixel-identical:

from astropy.coordinates import SkyCoord
from dr1_access import remote_rows_cutout            # demo/dr1_access.py
data, header = remote_rows_cutout(name, SkyCoord(ra, dec, unit="deg"), half_size_arcmin=0.5)  # BGMOD/RMS name

4. Catalogue: MER + morphology + photo-z

SELECT m.object_id, m.right_ascension, m.declination, m.flux_detection_total, m.flux_vis_sersic,
       m.point_like_prob, m.spurious_prob, m.det_quality_flag, m.deblended_flag,
       mo.sersic_sersic_vis_radius, mo.sersic_sersic_vis_index, mo.sersic_sersic_vis_axis_ratio,
       p.phz_median, p.phz_flags, c.phz_classification
FROM dr1.mer_catalogue_wide_survey AS m
JOIN dr1.mer_morphology_wide_survey AS mo ON mo.object_id = m.object_id
JOIN dr1.phz_photo_z_wide AS p ON p.object_id = m.object_id
JOIN dr1.phz_classification_wide AS c ON c.object_id = m.object_id
WHERE 1 = CONTAINS(POINT(m.right_ascension, m.declination), CIRCLE(58.198, -47.478, 0.05))
  AND c.phz_classification = 2          -- 2 = galaxy, 1 = star (the TAP description is swapped)
  AND m.spurious_prob < 0.7 AND m.det_quality_flag = 0

6. Calibrated single exposures (for LSB re-processing)

SELECT observation_id, instrument_name, filter_name, ra, dec, pa, duration, start_time_mjd, file_name
FROM dr1.calibrated_frame
WHERE 1 = CONTAINS(POINT('ICRS', ra, dec), CIRCLE('ICRS', 49.4903, -44.2381, 0.6))   -- frame centres near target
-- auxiliary BKG / WGT / PSF files: dr1.aux_calibrated (calibrated_frame_id = calibrated_frame_oid)

A VIS exposure is 7.3 GB (144 CCD quadrants × SCI/RMS/FLG) and a NIR exposure 0.8 GB (16 detectors), but the layout is regular. So demo/09_frame_cutouts.py fetches only the quadrants or detectors that cover your target, one ~50 MB range request each, and cuts the region out with each unit's own WCS. For a 1′ galaxy this means 0.9 GB for VIS+Y+J+H instead of 39 GB of whole files (see how much data for one galaxy).

uv run python demo/09_frame_cutouts.py --radius-arcmin 0.5 --bands VIS NIR_Y NIR_J NIR_H

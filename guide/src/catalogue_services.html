Catalogues at scale: IRSA HATS + LSDB

IRSA serves 57 DR1 catalogues (MER, PHZ, SPE, SIR combined spectra) as HEALPix-partitioned Parquet ("HATS") in a public AWS bucket. LSDB is the Python client. We checked it hands-on: the MER wide-survey copy is identical to the ESA DR1_R2 table (888,152,165 rows; same object_ids and values in a test cone).

import lsdb                                   # uv add lsdb s3fs
euclid = lsdb.open_catalog(
    "s3://nasa-irsa-euclid-dr1/contributed/dr1/hats/reformatted_catalogs/mer_catalogue_wide_survey",
    columns=["object_id", "ra", "dec", "flux_vis_sersic", "spurious_prob", "det_quality_flag"])
legacy = lsdb.open_catalog("http://slac.data.lsdb.io:10942/lsdb/legacysurvey_dr11.0_south",
                           columns=["OBJID", "RA", "DEC", "TYPE", "FLUX_R", "MASKBITS"])
matched = (euclid.cone_search(ra=58.198, dec=-47.478, radius_arcsec=300)
           .crossmatch(legacy, radius_arcsec=1.0, n_neighbors=1, suffixes=("_euclid", "_ls"),
                       suffix_method="all_columns")
           .compute())                         # nothing is read before .compute()

URL schemeuse s3://; the https:// form of the bucket opens but fails at .compute()
Column namesas ESA but lower case, with ra, dec, tileid instead of right_ascension, declination, tile_index; no release column; pyarrow dtypes (<NA>)
Speed5′ cone: HATS 51 s versus ESA TAP 9 s; 30′ cone (357k rows): 41 s versus 16 s. A cone reads whole ~1.3 GB partitions, and nothing is cached. Use TAP for single galaxies and HATS for survey-scale work and cross-matches.
Cross-match partnersGaia DR3, Legacy Surveys DR10.1 and DR11.0 North/South (DR11 on a SLAC server linked from data.lsdb.io; includes unWISE forced photometry), DESI DR1 redshifts, HSC PDR3 (one catalogue per band), AllWISE, NEOWISE, 2MASS. All Euclid catalogues have 10″ margins for edge-safe matching.

DR1 footprint

DR1-Foundation has no single survey-wide footprint file. The official LE3 VMPZ HEALPix maps (footprint, coverage, effective coverage, bit mask, depth, info maps) come per MER tile and band: Nside 16384 (12.9″), NESTED, COORDSYS = 'celestial', ~19,400 pixels (0.249 deg²) and ~240 KB per tile file. For quick "is it in DR1?" checks and for cross-matching, build a MOC.

from pathlib import Path
import astropy.units as u
from mocpy import MOC
moc = MOC.from_fits(Path.home() / "data/euclid/dr1_demo/footprint/dr1_wide_vis_tiles_moc_order13.fits")
moc.contains_lonlat([58.198] * u.deg, [-47.478] * u.deg)      # -> array([ True])
